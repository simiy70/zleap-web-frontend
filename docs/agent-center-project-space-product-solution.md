# Zleap Agent 会话与项目协作产品方案

## 1. 产品心智

- **Agent 是联系人。** 打开即对话，动态、自动化任务和能力配置是这个 Agent 的个人页签。
- **项目是协作空间。** 打开即进入协作现场，群聊和当前工作同时可见；完整看板与资料是另外两个工作区域。
- 页面直接呈现列表、聊天、看板和资料，不长期展示功能解释。权限规则放入按钮状态、Tooltip 和设置抽屉。

## 2. Agent

### 2.1 中心与个人页

中心保留消息、通讯录、自动化、发现四个入口。Agent 个人页保留消息、动态、自动化任务、能力配置四个 Tab，默认进入消息。

Agent 在通讯录、消息列表、标题和任务归属处都展示同一套头像、名称、在线状态与来源身份。本地接入 Agent 统一展示「本地」徽标。

### 2.2 会话模型

| 来源 | `sessionMode` | 行为 |
| --- | --- | --- |
| Zleap 创建、模板创建、官方添加 | `single` | 单一持续会话，不出现历史会话入口 |
| 本地接入 | `multiple` | 右上角提供历史会话弹层，默认打开最近会话 |

本地会话弹层支持搜索、新建、切换、重命名、归档和删除。会话按 `updatedAt` 倒序显示，当前会话使用橙色选中态。数据使用 `archived` 标记归档状态。

### 2.3 引导式自动化

自动化任务只使用 `enabled: boolean`：

- `true`：正常执行
- `false`：暂停

从单 Agent 或全局自动化入口创建时，先进入对应 Agent 的消息：

1. Agent 询问持续目标。
2. 用户用自然语言回答。
3. Agent 生成包含名称、触发条件和推送位置的 `AutomationDraft` 确认卡。
4. 用户确认后生成 `AutomationTask`，默认正常执行。

取消或未确认的配置不会产生任务。项目工作项不进入自动化总览。

## 3. 项目空间

### 3.1 创建与导航

创建项目只填写项目名称。系统默认创建私密项目、设置当前用户为负责人并生成“项目总群”，完成后直接进入协作页。

项目顶部只保留三个同级区域：

- **协作**：默认入口，群聊与当前工作同时可见。
- **工作**：完整三列项目看板。
- **资料**：文件、信息源和 Agent 产出。

项目概览由项目标题或概览按钮打开。参与者通过头像组进入管理抽屉；权限、通知、归档和删除进入设置或更多菜单。

### 3.2 协作现场

协作页使用三段布局：

- 左侧：项目群聊列表。
- 中间：当前群聊与输入区。
- 右侧：待处理和进行中的当前工作。

用户可以通过“分配工作”直接创建，也可以在群聊中使用自然语言。聊天识别出的工作先生成确认卡，确认后同步到当前工作和完整看板，并保留来源会话与消息标识。

### 3.3 项目工作

`ProjectWorkItem` 使用三种状态：

- `todo`：待处理
- `doing`：进行中
- `done`：已完成

工作项可分配给人类成员或项目 Agent。详情抽屉可以编辑标题、说明、负责人、截止时间和状态；原型不依赖拖拽完成流转。

### 3.4 空间概览与能力边界

概览抽屉展示项目说明 `project.md`、成员、Agent、可用 Skills、已授权 Tools、已授权信息源、最近资料、权限和负责人。

- `effectiveSkills`：从项目 Agent 的 Skills 聚合去重，并保留所属 Agent。
- `effectiveTools`：项目 Agent 的 Tools 与项目授权 Tools 的交集。
- `effectiveSources`：项目明确授权的信息源和资料。

Skills 随项目 Agent 加入或移除即时更新。Tools 与信息源必须在项目设置中显式授权。项目 Agent 不读取私人对话、单 Agent 自动化任务或未授权的个人信息源。

## 4. 原型边界与验收

- 数据继续使用 React 会话状态模拟，不连接真实后端。
- Agent 头像在全部页面保持圆形。
- 系统 Agent 没有会话管理入口，本地 Agent 可以管理多个历史会话。
- 自动化创建在消息内完成，确认前不写入任务。
- 项目创建完成后进入项目总群，协作页同时展示群聊与当前工作。
- 工作项同步到三列看板，并与 Agent 自动化任务保持独立。
- 项目顶层仅有协作、工作、资料。
- 概览抽屉能随 Agent、Tools 和信息源授权变化即时更新。
- 主页面不出现重复的模块介绍文案，只保留用户内容、必要状态、空状态、错误和确认信息。
