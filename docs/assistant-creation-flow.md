# Zleap 助手创建与外部 Agent 接入流程

## 目标

让用户在同一个入口中完成两类任务：

1. 从零创建一个 Zleap 原生助手。
2. 将设备中已有的外部 Agent 接入 Zleap。

创建助手与连接 Zleap 信息源是两个连续但解耦的阶段。助手创建成功后，即使用户暂时不配置 MCP，也可以进入助手详情页继续完善。

## 总体信息架构

用户点击「创建助手」后，第一层只做一个选择：

- **创建 Zleap 助手**：适合从零开始，支持手动编写、导入文件和系统模板。
- **接入外部 Agent**：适合已经在本地工具中使用 Agent 的用户，通过终端配对后选择并导入。

不要在第一屏同时平铺所有创建方式。先区分“新建”与“接入”，再展示各自的下一步，可以减少用户理解成本。

## 路径一：创建 Zleap 助手

### 1. 选择创建方式

展示三种方式：

| 创建方式 | 适用用户 | 主操作 |
| --- | --- | --- |
| 手动创建 | 已经知道助手职责，准备自己编写提示词 | 开始编写 |
| 导入 `AGENTS.md` | 已有可复用的 Agent 配置文件 | 选择文件 |
| 从模板创建 | 希望快速开始，或不熟悉提示词结构 | 浏览模板 |

### 2A. 手动创建

表单建议包括：

- 助手名称
- 一句话简介
- 系统提示词
- 图标与头像色调

在提示词输入区提供「AI 完善」按钮，而不是放在整个表单末尾。点击后：

1. 系统基于原始提示词生成优化版本。
2. 用对比或高亮方式展示修改。
3. 用户可以「采用优化」「保留原文」或继续编辑。

AI 完善不能直接覆盖用户原文；在用户确认前保留原始内容。

### 2B. 导入 `AGENTS.md`

流程：

1. 拖拽或选择文件。
2. 校验文件类型、大小和可解析性。
3. 解析名称、描述、提示词、工具与依赖。
4. 展示导入预览和警告。
5. 用户确认后创建。

需要区分三类解析结果：

- **可直接导入**：所有核心字段都能识别。
- **需补充信息**：缺少名称、描述等非结构化信息，允许用户补齐。
- **无法导入**：文件损坏或格式完全不兼容，给出明确原因和处理建议。

导入预览中应标记 Zleap 暂不支持的工具或配置，不能静默忽略。

### 2C. 从模板创建

模板列表支持按场景或角色分类，并优先展示：

- 模板名称与用途
- 适合谁使用
- 已包含的能力
- 需要后续连接的信息源

用户点击模板后先进入预览，再选择「使用此模板」。随后进入与手动创建相同的编辑页，允许修改名称、简介和提示词，避免模板成为不可编辑的黑盒。

## 路径二：接入外部 Agent

### 1. 连接设备

系统生成一次性终端命令，并同时提供：

- 复制命令
- 命令用途说明
- 支持的 Agent 类型
- 隐私与扫描范围说明
- 配对有效期

建议将文案从“识别设备中所有本地 Agent”收敛为：

> 仅扫描已支持工具的标准 Agent 配置目录，不读取对话内容和无关文件。

命令执行后，页面自动进入检测状态，并提供「我已运行，重新检测」作为手动兜底。

### 2. 选择要接入的 Agent

发现结果以列表展示，每项至少包括：

- Agent 名称
- 来源工具
- 本地路径
- 最近更新时间
- 兼容状态
- 预计导入内容

支持多选，但需要明确：

- 同名助手的处理方式：跳过、覆盖或创建副本。
- 不兼容能力的处理方式：继续导入可兼容部分，或取消。
- Agent 的接入模式。

接入模式建议明确为以下二选一：

- **复制导入**：将当前配置复制到 Zleap，之后双方独立修改。
- **保持同步**：保留与本地配置的关联，后续可以再次同步。

如果第一期暂不支持同步，只提供「复制导入」，并直接说明导入后不会自动跟随本地文件更新。

### 3. 导入确认

用户勾选 Agent 后，先展示导入摘要：

- 将创建多少个助手
- 每个助手会导入哪些内容
- 哪些内容需要用户补充
- 哪些能力暂不兼容

完成后进入结果页，分别展示成功、需补充和失败的 Agent，允许用户单独重试失败项。

## 创建完成：连接 Zleap 信息源

助手创建完成后显示成功结果，并询问是否连接 Zleap 信息源能力：

- **现在连接**：生成 MCP 配置指令，引导用户在对应 Agent 中执行。
- **稍后连接**：进入助手详情页，并保留「连接信息源」待办入口。

这里应强调连接带来的具体价值，例如搜索团队文档、读取日程、访问知识库，而不是只展示“MCP”技术名词。

建议将 MCP 配置设计为独立状态：

- 未连接
- 等待执行
- 检测连接
- 已连接
- 连接失败

连接失败不应回滚已经成功创建的助手。

## 推荐页面结构

```text
创建助手入口
├── 创建 Zleap 助手
│   ├── 手动创建
│   │   └── AI 完善提示词
│   ├── 导入 AGENTS.md
│   │   └── 解析与确认
│   └── 从模板创建
│       └── 模板预览与编辑
└── 接入外部 Agent
    ├── 复制终端命令并连接设备
    ├── 扫描并选择 Agent
    ├── 处理冲突与兼容问题
    └── 导入结果
        └── 可选：连接 Zleap 信息源 MCP
```

## 关键交互原则

1. **创建成功与 MCP 成功解耦**：避免最后一步失败导致用户误以为全部失败。
2. **所有自动修改都可预览和撤销**：AI 完善、文件解析和兼容转换均需用户确认。
3. **扫描范围透明**：终端命令执行前说明会读取什么、不会读取什么。
4. **批量操作按单个 Agent 返回结果**：部分失败不影响其他 Agent。
5. **统一回到同一编辑模型**：手动、文件和模板最终都落到可编辑的助手配置页。

## 首期范围建议

第一期建议先支持：

- 手动创建与 AI 完善。
- 单个 `AGENTS.md` 文件导入。
- 系统模板创建。
- 本地 Agent 扫描与复制导入。
- 创建完成后的可选 MCP 指引。

第一期暂不承诺：

- 本地 Agent 配置实时同步。
- 自动修改用户本地配置文件。
- 对所有 Agent 工具和自定义目录的无差别扫描。

这些边界可以降低权限、兼容和数据一致性风险，同时保留后续升级空间。

## 验收标准

- 用户从「创建助手」入口最多一次选择即可进入目标路径。
- 三种原生创建方式最终都能进入统一的可编辑配置页。
- AI 完善不会在确认前覆盖原始提示词。
- 文件解析失败时会指出具体原因。
- 本地扫描前会展示扫描范围和隐私说明。
- 用户能看到每个外部 Agent 的来源、路径与兼容状态。
- 批量导入时，单项失败不会阻断其他项。
- MCP 对接可以跳过，并能从助手详情页再次发起。
- MCP 对接失败不会删除或回滚已创建的助手。
